# 担当範囲と課題解決

本プロジェクトは、教員を含む10名のプロジェクトで、Webサイト開発は私を含む5名で行いました。私は開発の進行を担いながら、下記を中心に実装・改善しました。

| 担当 | 課題 | 実施内容 |
|---|---|---|
| ログイン認証 | 学外の利用者が取引へ参加できないようにする | Google OAuth 2.0を導入し、サーバー側で指定ドメインを検証。ログイン後ページとAPIをセッションで保護 |
| カメラ・画像登録 | スマートフォンから教材の表紙を簡単に登録したい | 外向きカメラを優先して起動し、撮影画像をブラウザ上で縮小・JPEG化して容量を削減 |
| 受け取り控え | ロッカー情報を後から確認できるようにしたい | 控え部分を画像化し、対応端末では共有機能、非対応環境ではダウンロードを使用 |
| マイページ | 出品と取引の状態が分かりにくい | 譲り手・貰い手の役割、進行状態、期限、残り時間をカード形式で表示 |
| お問い合わせ | 利用中の問題を運営側へ伝える窓口がない | ログイン情報を利用したフォームと、入力検証・二重送信防止を実装 |
| GAS・データ連携 | 画面追加に合わせて取得・更新処理が必要 | マイページや問い合わせに必要なアクションとデータ形式を追加・調整 |
| レスポンシブ対応 | スマートフォンで検索やメニューが扱いにくい | 実機確認を行い、検索欄、絞り込み、ヘッダー、画像選択などを改善 |
| 公開・運用 | 開発環境だけでなく継続公開する必要がある | Docker、Nginx、HTTPS、さくらVPSを利用して公開し、ログやAPI応答を調査 |

## 特に意識したこと

### 利用者の手間を減らす

金銭のやり取り、対面、日程調整を不要にし、教材の登録から受け取りまで迷いにくい流れを目指しました。期限は日時だけでなく残り時間も表示しています。

### フロントエンドだけに頼らない認証

ログイン画面の表示制御だけではなく、OAuth完了時のドメイン確認、保護ページ、APIの各段階をサーバー側で確認する構成にしました。

### 端末ごとの差を考慮する

カメラやファイル保存はブラウザ・OSによって動作が異なるため、対応機能を判定し、利用できない場合の代替手段とエラーメッセージを用意しました。

## コード例について

`examples/`には、上記のうち認証、カメラ、画像保存の考え方が分かるコードを掲載しています。共同開発リポジトリのファイルをそのまま公開したものではなく、秘密情報とプロジェクト固有情報を除き、採用向けに独立した例へ再構成しています。

# システム構成・処理フロー

## 全体構成

```text
スマートフォン／PCブラウザ
        │ HTTPS
        ▼
      Nginx
        │ リバースプロキシ
        ▼
 Node.js / Express
   ├─ Google OAuth 2.0によるログイン認証
   ├─ 指定ドメインによる利用者制限
   ├─ セッション管理
   ├─ 教材画像のアップロード・配信
   └─ Google Apps ScriptとのAPI連携
                         │
                         ▼
                 Googleスプレッドシート
                 教材・取引情報を管理
```

公開環境では、Docker ComposeでNode.jsとNginxをコンテナ化し、さくらVPS上で稼働させています。NginxでHTTPS通信を受け、認証やAPI処理をExpressへ転送します。

## ログイン

1. 利用者がGoogleログインを開始する
2. Google OAuth 2.0でプロフィールとメールアドレスの利用許可を得る
3. サーバー側でメールアドレスのドメインを検証する
4. 条件を満たす利用者だけセッションを作成する
5. 認証が必要な画面とAPIは、セッションの有無を確認して保護する

## 教材の登録

1. スマートフォンのカメラまたは写真ライブラリから表紙画像を取得する
2. ブラウザ上で最大辺と画質を調整し、アップロード容量を抑える
3. 教材名、授業名、教員名、状態とともにサーバーへ送信する
4. 画像はサーバーの永続領域、教材情報はスプレッドシートへ保存する

## 受け取り申し込み

1. 貰い手が教材を選び、受け取りを申し込む
2. 取引状態と期限を更新する
3. 譲り手・貰い手それぞれのマイページに役割と進行状況を表示する
4. 受け取り控えをブラウザ上で画像化し、スマートフォンでは共有画面から写真ライブラリへ保存できるようにする

## セキュリティと公開時の配慮

- OAuthのクライアントシークレットなどは環境変数で管理
- 認証が必要なHTMLとAPIの両方をサーバー側で保護
- リダイレクト先をアプリ内の安全なパスに限定
- 画面へ動的に出す文字列をエスケープし、意図しないHTMLとして解釈されないようにする
- 本ポートフォリオでは実ドメイン、認証情報、GAS URL、暗証番号、個人情報、実運用データを非掲載
